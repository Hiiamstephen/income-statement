How the income statement app works

1. What was built

One JSON ledger, one calculation module, one HTTP server, one browser page, and a standard-library test suite. The accounting math is isolated from HTTP and display code.

ledger.jsonAccounts and journal entries
statement.pyValidates and calculates
app.pyServes HTML and JSON
index.htmlCollects dates and renders

test_statement.py checks calculations and the API. README.md, NOTES.md, DESIGN_PLAN.md, and WALKTHROUGH.md document usage, decisions, and review prep.

2. From click to result

  1. Date form: index.html defaults to Q1 2026 and builds a query using URLSearchParams.
  2. HTTP request: browser sends GET /income-statement?start=…&end=…; loading state appears while waiting.
  3. Route validation: app.py parses the query, rejects missing or repeated dates, calls the calculation, and maps invalid input to HTTP 400 JSON.
  4. Statement calculation: statement.py filters ledger entries and returns account rows, sections, subtotals, and final totals as decimal strings.
  5. DOM rendering: page builds rows with DOM methods and textContent; errors are shown to the user. Negative amounts use parentheses.
Form → GET /income-statement → validate query → calculate from ledger → JSON → render table
app.pyLoads ledger once at startup, serves /, serves the API, returns 404 for unknown paths, binds to localhost. PORT can override 8000.
index.htmlHas no frontend build step. It formats signed API strings, groups thousands, and creates accessible table headings.

3. Accounting logic and exact money

Validate source data early

load_ledger checks account IDs/types, dates, unique entry IDs, statuses, references, amount formats, minimum lines, and balanced debits and credits. Bad source data fails at startup.

Represent money as integer cents

parse_cents converts strings such as 18500.00 to integers. Arithmetic stays exact; money converts back to fixed two-decimal strings.

Why: binary floating point cannot represent every decimal cent exactly; integer cents avoid rounding drift.

Dates must be real ISO calendar dates and endpoints are inclusive. Only posted entries within the range count. Revenue is credits minus debits; expenses are debits minus credits. Credits to expense accounts and debits to contra-revenue therefore become negative.

Revenue          = operating revenue + contra-revenue
Gross profit     = revenue − cost of goods sold
Operating income = gross profit − operating expenses
Net income       = operating income + other income

Decisions recorded in NOTES.md: inactive means no new postings, so historical activity remains; drafts and voids are excluded; cash collection is not revenue; subscription revenue counts when recognized; January rent stays in January as recorded; no missing accrual or allocation is invented.

Response shape

Top-level company, currency, and period; four ordered sections with account rows and subtotals; then gross profit, operating income, and net income. Amounts are signed strings such as -44480.14.

5. How correctness was checked

The suite targets errors that could otherwise produce a page that looks plausible.

CoverageBug it would catch
Independent Q1 account and total targetsWrong sign, missing entry, or bad subtotal
Inclusive dates and posted-only filterBoundary omissions or draft/void inclusion
Accounting meaning casesCash collection treated as sales; invented rent allocation; inactive history discarded
Negative and empty periodsReversal sign bugs or missing zero rows
Month-to-quarter reconciliationPeriod logic mismatch between individual months and Q1
Malformed ledger checksUnknown account, unbalanced entry, invalid precision accepted
HTTP contract and source parityMalformed query behavior or local fixture drifting from assignment data

Prior run reported 10 passing tests. Re-run to verify this checkout.

6. Run it yourself

Requires Python 3.10 or newer. No install step.

python3 app.py
# Open http://127.0.0.1:8000/

python3 -m unittest -v

curl 'http://127.0.0.1:8000/income-statement?start=2026-01-01&end=2026-03-31'

Useful review cases: Q1 net income is (USD 44,480.14); March 20 has a USD 100 vendor credit and USD 100 net income; an empty month returns all zero account rows.

Structure: standard-library only, no database or deployment infrastructure. The pure calculation function and explicit JSON contract keep the project understandable and ready for a pairing-session change.
